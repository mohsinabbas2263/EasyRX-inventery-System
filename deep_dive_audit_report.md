## 1. Sync Engine Implementation

### 🔑 Idempotency Key Validation
We use a `local_uuid` generated by the client and an `idempotency_key` (if provided) to ensure each document is processed exactly once.
```typescript
private async isDuplicate(item: SyncQueue): Promise<boolean> {
  const table = this.getTableName(item.documentType);
  const exists = await this.dataSource.query(
    `SELECT 1 FROM "${table}" WHERE "local_uuid" = $1 AND "company_id" = $2`,
    [item.localUuid, this.tenantContext.companyId]
  );
  return exists.length > 0;
}
```

### ⚔️ Conflict Detection & Resolution
We detect conflicts by comparing the server's `updated_at` with the client's last sync reference. Currently, we use a "Conflict Marked" strategy for manual resolution or automated LWW (Last Write Wins).
```typescript
const centralTime = new Date(centralRecord[0].updated_at).getTime();
const clientRefTime = new Date(item.payload?.clientLastSyncTime || 0).getTime();
if (centralTime > clientRefTime) return centralRecord[0]; // Conflict!
```

### ⏳ Retry with Exponential Backoff
Failed syncs are rescheduled with increasing wait times ($retryCount^2$ minutes).
```typescript
const waitMinutes = Math.pow(item.retryCount, 2);
const nextRetry = new Date();
nextRetry.setMinutes(nextRetry.getMinutes() + waitMinutes);
```

## 3. FEFO Algorithm (Batch Selection)
The `BatchSelectionService` ensures pharmaceutical safety.

### 📅 FEFO Selection Code
```typescript
const batches = await this.batchRepository.find({
  where: {
    productId,
    branchId,
    quantityOnHand: MoreThan(0),
    expiryDate: MoreThan(new Date()), // PREVENTS EXPIRED BATCHES
  },
  order: { expiryDate: 'ASC' }, // NEAREST EXPIRY FIRST
});
```

### 💧 Partial Consumption
Logic handles splitting requests across multiple batches:
```typescript
const allocate = Math.min(Number(batch.quantityOnHand), remaining);
allocations.push({ batchId: batch.batchId, quantity: allocate });
remaining -= allocate;
```
